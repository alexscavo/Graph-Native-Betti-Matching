# Research storage cleanup — 2026-10-16

## Outcome

User requested a smaller project while retaining present/future comparison evidence and journal material. No jobs were active before mutation. No training, data split, model architecture, loss or evaluation procedure changed.

- Deleted **70 explicitly reviewed files, freeing 100.38 GiB** on SCRATCH: 66 smoke/cancelled checkpoint files and four large initial random-prediction JSON files from the cancelled configuration.
- Consolidated **43 startup/abandoned run directories**, preserving **1,925 regular files** in a byte-verified archive. Original regular payload 3.15 GiB → archive 0.87 GiB; approximately 2.28 GiB additional payload reduction. Original directories contain `ARCHIVED.md` restore instructions.
- Removed a Codex crash core dump from projects (414.23 MiB allocated; 1.39 GiB apparent). It is not research evidence.
- Verified **119 retained checkpoint files** in the audited spline/source-transfer runs still exist with unchanged size, modification timestamp and inode. Other historical Graph-Native-Betti-Matching checkpoints outside this audit were left intact.
- Total reduction is approximately **103 GiB** across SCRATCH and WORK. No original dataset, derived target cache, scientific comparison checkpoint, final test prediction, Git history or existing user edit was removed.

## Why these files were disposable

Smoke runs performed approximately three startup-verification updates. Their weights are neither trained comparison models nor approved initialization checkpoints. Configurations, finite-loss checks, logs and measured smoke outputs are retained in the archive.

The original `plant_generalization_20261014/runs/pretrain_mixed` and `pretrain_vessels` were explicitly cancelled and superseded by the from-scratch batch32/domain-loss1.0 restart. Their weights and very large step-zero random predictions have no role in the controlled source comparison. Their sample membership, configurations, aggregate step-zero metrics, later measured results and W&B records are archived. The shared `plant_generalization_20261014/plants-k8` dataset is **retained** because current plant and IXI experiments depend on it.

The first failed controlled-unfreezing, frozen-head and scratch-local attempts, Catmull–Rom smoke, and IXI overfit initial attempts have their full remaining evidence archived. Successful replacements stay active. No pilot was discarded merely for showing poor performance.

This archive is on SCRATCH, so consolidation is **not a durable backup**. The existing dataset-recovery archives on STORE remain untouched. Deleted startup/cancelled weights are not included in the archive; reproducing them would require rerunning their recorded configurations.

## File-count quota: important distinction

At audit time `df -i` showed approximately 465,855 of 500,000 entries used (94%) for WORK, while the per-user `lfs quota` query reported approximately 69,326 entries and no explicit user inode limit. The full user projects tree accounts for only approximately 6,500 entries; most of the broader WORK allocation lies outside these project folders. SCRATCH's per-user query reported approximately 2.2 million entries and no explicit user inode limit.

Consequently, pruning SCRATCH model bytes does **not** solve the broader WORK file-count pressure. The project is already small in file count. Unrelated editor installations, other users' files and account-wide data were not removed to make the reported quota appear better. A further WORK quota intervention needs an account-level ownership review, not deletion of useful scientific evidence.

## Reproducibility and ongoing retention

Exact audit, removal plan, deletion log, archive membership/checksums and post-cleanup checks are under `experiments/storage_cleanup/20261016/`. The cleanup scripts are deliberately fixed to this reviewed manifest, not a recurring age-based deletion service.

For future experiments:

1. Keep compact config, dataset IDs, initialization, metrics and interpretation for every scientific comparison, including negative results.
2. Keep best and final/resume checkpoints for the current comparison suite and reusable pretraining sources; do not silently strip optimizer state from resumable files.
3. Delete startup-only checkpoints after a successful smoke check, retaining its log/summary.
4. Archive superseded startup attempts after reviewing references, and verify archive bytes before removing originals.
5. Leave large arrays/checkpoints on SCRATCH and compact reports in Git. Keep documentation separate from experiment execution artifacts.

No broad code refactor was needed: misleading navigation was updated, while live configurations and data paths remain reproducible.
